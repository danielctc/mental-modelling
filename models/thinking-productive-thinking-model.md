# Productive Thinking Model

## Trigger Card

When the problem is known but the solution isn't:

1. **What's going on?** — understand the problem and the target future.
2. **What's success?** — define criteria (DRIVE).
3. **What's the question?** — write catalytic "How might we..." questions.
4. **Generate answers** — many, without judging.
5. **Forge the solution** — evaluate against step 2's criteria, then develop the winner.
6. **Align resources** — who, what, when.

Skip for small problems; this is a full workshop-grade process.

## Overview

Created by Tim Hurson ("Think Better"). Its value over ad-hoc brainstorming is that success criteria are defined **before** ideas are generated — so evaluation is against a standard set while you were still honest, not against whichever idea you fell in love with.

**Core Principle:** Define success before you generate solutions. Otherwise you'll define success as whatever your favourite idea does.

## When to Use

- A defined problem needing a creative solution
- Team workshops and offsites
- Product or service design
- Process redesign
- Any problem where "just brainstorm it" has already failed once

## When NOT to Use

- **The problem isn't defined yet** → `thinking-abstraction-laddering` or `thinking-issue-trees` first.
- **The solution is known and it's an execution problem.**
- **Small or reversible decisions.** Six steps is a lot of ceremony.
- **You're solo and time-boxed** — run steps 2, 3 and 4 only.
- Crisis response. Run the incident; do this at the postmortem.

## The Process

### Step 1: Ask "What's going on?"
Understand before solving. Guiding questions:
- What's the problem exactly?
- What's the impact of it?
- What do I already know? What information do I have?
- Who is involved?
- **What's the vision of the future once this is solved?** (Hurson's "Target Future")

Document the answers. You'll need them at step 5.

### Step 2: Ask "What's success?"
Define what success looks like in that Target Future, using **DRIVE**:

| Letter | Question |
|--------|----------|
| **D**o | What do you want the solution to *do*? |
| **R**estrictions | What must it *not* do? (`thinking-inversion` helps here) |
| **I**nvest | What resources can we put in? |
| **V**alues | What values should the solution have? |
| **E**ssential outcomes | What must be true at the end? |

Cycle until success is clear. **This is the step people skip, and skipping it is why step 5 turns into an argument about taste.**

### Step 3: Ask "What's the question?"
Generate the questions that must be answered to reach the Target Future — Hurson's "catalytic questions". Phrase them as "How might we...?" or "How can I...?"

Good catalytic questions are specific enough to answer and open enough to have many answers.

### Step 4: Generate answers
Brainstorm against the catalytic questions. Many answers. **No judging at this stage** — evaluation is step 5's job and mixing them kills the volume.

Escalate if the ideas are thin: `thinking-zwicky-box`, `thinking-first-principles`, `thinking-triz`.

### Step 5: Forge the solution
Now evaluate. Score each idea against the success criteria from step 2 — `thinking-decision-matrix` makes this quick and keeps it honest.

Then *develop* the winner: what would make it better? How can it fit the criteria more fully? A raw idea is not a solution; forging is the difference.

### Step 6: Align resources
Move toward execution: who does what, by when, with what. An unresourced solution is a wish.

## Application Patterns

### Compressed solo version (20 minutes)
```
1. Target Future:      one sentence on what "solved" looks like
2. Success criteria:   3-5 bullets, written BEFORE any ideas
3. Catalytic question: one "How might we...?"
4. Generate:           10 ideas, no filtering
5. Forge:              score against the criteria, develop the top one
6. Resource:           first action, owner, date
```

### Workshop version
Half a day. Steps 1-2 together, step 3 together, step 4 in silence then shared (silent generation beats group brainstorm for volume and variety), steps 5-6 together.

## Common Failure Modes

| Failure | Fix |
|---------|-----|
| Skipping step 2 | Then step 5 is taste. Write criteria before ideas, always |
| Judging during step 4 | Separate them in time; name the rule out loud |
| Vague catalytic question | "How might we improve things" answers itself badly. Be specific |
| Stopping at step 5 | An unresourced solution doesn't happen |
| Running it on an undefined problem | Frame first |

## Verification Checklist
- [ ] Target Future written as a concrete vision
- [ ] DRIVE criteria written before any ideas were generated
- [ ] Catalytic questions specific and open
- [ ] Generation and evaluation kept separate
- [ ] Winner scored against step 2's criteria, not against preference
- [ ] Winner developed further, not just selected
- [ ] Resources, owner and date named

## Key Questions
- "What does the world look like when this is solved?"
- "What must the solution do, and what must it not do?"
- "What's the real question we need to answer?"
- "Am I judging while I'm supposed to be generating?"
- "Who does what by when?"
