# Zwicky Box (Morphological Analysis)

## Trigger Card

When you need a large number of genuinely different solutions:

1. **Identify 3-6 independent attributes** of the solution space (columns).
2. **List many values under each** — don't filter, don't check feasibility yet.
3. **Combine one value per column** to form a whole solution.
4. **Work through combinations** systematically or randomly, including the odd ones.

Skip if one or two obvious solutions already fit — this is for when they don't.

## Overview

Created by Fritz Zwicky, the Swiss astronomer who also proposed dark matter and neutron stars. It applies two principles of creativity: **decomposition** (break the problem into parts) and **forced association** (combine parts that wouldn't naturally go together).

Ordinary brainstorming converges on familiar whole solutions. The Zwicky box makes you build solutions from components, which reaches combinations nobody would have proposed intact.

**Core Principle:** Decompose into independent attributes, then force combinations across them.

```
  ┌──────────────┬──────────────┬──────────────┬──────────────┐
  │ Audience     │ Format       │ Delivery     │ Revenue      │
  ├──────────────┼──────────────┼──────────────┼──────────────┤
  │ Small teams  │ Newsletter   │ Email        │ Subscription │
  │ Managers     │ Podcast      │ Web          │ Sponsorship  │
  │ Vendors      │ Dashboard    │ API          │ Free + upsell│
  │ Students     │ Live event   │ Chat         │ Pay-per-use  │
  └──────────────┴──────────────┴──────────────┴──────────────┘
       ↓ combine one per column ↓
  "Vendors + Dashboard + API + Pay-per-use"  ← nobody proposes this whole
```

## When to Use

- Complex problems with several dimensions
- You need volume — many options, not the best one yet
- Brainstorming has produced only the obvious three
- Product, service or business model design
- Naming, positioning, campaign concepts
- Team workshops — each person can own a column

## When NOT to Use

- **The problem is one-dimensional.** Nothing to combine.
- **You need the best option, not more options.** This diverges; use `thinking-decision-matrix` to converge afterwards.
- **Attributes aren't independent.** If choosing a value in column A forces a value in column B, the combinations are illusory — redefine the attributes.
- **Time pressure with an adequate solution already in hand.**
- When the constraint is execution, not ideas.

## The Process

### Step 1: Define the problem clearly
Before decomposing. A vague problem yields vague attributes.

### Step 2: Identify attributes — the critical step
Break the problem into key categories that define the solution space. They must be **logically independent** so combinations are valid.

**Tip:** take an existing example of a solution, list its parts, and reverse-engineer the attributes from there. Easier than inventing them from nothing.

3-6 attributes. Two isn't a box; eight is a combinatorial explosion nobody will work through.

### Step 3: Fill in values
Many per column. **Do not filter and do not check feasibility.** "What's possible" is the constraint you're deliberately suspending — impossible values often combine into possible solutions.

### Step 4: Generate combinations
Pick one value per column. Options:
- **Systematic** — work through all combinations (a 4×5 box gives 625; sample it)
- **Random** — pick blind. Surprisingly productive
- **Focused** — fix one attribute you're committed to, vary the rest

Stay open-minded. Combinations that seem absurd at first are exactly what the tool exists to surface — dismiss them after considering them, not before.

### Step 5: Converge
Now filter. Take the shortlist into `thinking-decision-matrix` or score against success criteria.

## Application Patterns

### Product/feature design
Attributes: target user, core job, unique mechanism, delivery surface, pricing model.

### Redesigning a process
Attributes: who initiates, trigger, channel, frequency, who decides, what's recorded. Combining "customer initiates" with "async channel" and "auto-decided" describes self-service — which nobody proposes as a whole when the current process is a meeting.

### Content formats
Attributes: audience, angle, format, length, distribution, cadence. Good for breaking out of "another 1,200-word article".

### Naming and positioning
Attributes: metaphor domain, word origin, length, tone, structure.

## Verification Checklist
- [ ] Problem stated before decomposing
- [ ] 3-6 attributes, and they're genuinely independent
- [ ] Values generated without filtering for feasibility
- [ ] Combinations actually generated, not just the box admired
- [ ] Odd combinations considered before dismissal
- [ ] Converged with a separate tool rather than picking a favourite

## Key Questions
- "What are the independent dimensions of this solution?"
- "If I look at an existing solution, what parts does it have?"
- "Am I filtering values too early?"
- "What does this weird combination actually describe?"
- "Have I generated enough to be past the obvious ones?"
